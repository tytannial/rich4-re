# RAW 裸位图格式（无头 16bit 位图块）

> MKF 内**无魔数、无自描述头**的原始位图块。像素为 **16bit RGB555**，逐行连续，
> 尺寸不写在资源里，而由**调用方按 index 硬编码**。逆向自 `sub_450441`（加载管线）
> 与 `convertPixelFormat`(`sub_451801`)，并经抽查解码成图核对。

## 与 SPR/SMP 的区别

| | 魔数 | 头 | 调色板 | 尺寸来源 | 像素格式 |
|--|------|----|--------|----------|----------|
| SPR | `SPR\0` | 有（entry 表） | 有(512B) | 自描述 | 8bit 索引 |
| SMP | `SMP\0` | 有（entry 表） | 无 | 自描述 | 16bit 直接色 |
| **RAW** | **无** | **无** | **无** | **按 index 硬编码** | **16bit 直接色** |

## 加载管线中的处理

`sub_450441` 读取资源后：
1. 若 `compressed_size != decompressed_size` → LZHUF 解压；
2. 若资源头 `data_length != 0` → 对 `[data_offset, data_offset+data_length)` 调
   `convertPixelFormat`，把 16bit 像素从资源内格式转当前显示格式；
3. **仅当**前 3 字节为 `SPR`/`SMP` 才调 `relocateFrames`。

RAW 块无魔数，故**跳过第 3 步**，只经历格式转换。其 MKF 资源头普遍
`data_offset=4`、`data_length=size-4`（即跳过最前 2 个像素不做转换，属转换细节，
不影响"整块即 16bit 像素"这一事实）。

## 像素格式

- 小端 `u16`，按 **RGB555** 解释：`r=(v>>10)&0x1F, g=(v>>5)&0x1F, b=v&0x1F`（各 5bit）。
- 与 SMP 相同，但 SMP 有头可自描述，RAW 没有。
- 无透明通道；`0x0000` 是黑色而非透明（插画/背景含真实黑色内容）。

## 已确证的尺寸族（抽查解码成图）

| MKF | index | 大小(B) | W×H | 用途 | 抽查证据 |
|-----|-------|--------:|-----|------|----------|
| Data.mkf | 4–127 | 80000 | 200×200 | 事件/节日卡插画 | `[4]` "元旦"卡（怀表+派对元素）清晰 |
| Data.mkf | 441–516 | 194776 | 388×251 | 事件/结局大插画 | `[441]` 持棒男、`[442]` 牢房囚犯 清晰 |
| jump.mkf | 0–7 | 614400 | 640×480 | 跳伞小游戏照片背景 | `[0]` 圆山大饭店照片 清晰 |
| Panel.mkf | 92 | 614400 | 640×480 | 界面背景（南天门） | `[92]` 台阶+仙女+道具栏 清晰 |

> 尺寸推断方法：`W×H×2 == decompressed_size`，在合理范围内取唯一整除解。
> 例：`194776/2 = 97388 = 388×251`（380–470 内唯一整除宽度）；`80000/2 = 40000 = 200×200`。

## 解码要点（伪码）

```python
# 已知 (mkf, index, W, H)：
blob = mkf.payload(entry)           # 解压后原始字节
for y in range(H):
    for x in range(W):
        v = u16le(blob, (y*W + x) * 2)
        r, g, b = ((v>>10)&0x1F)*255//31, ((v>>5)&0x1F)*255//31, (v&0x1F)*255//31
```
